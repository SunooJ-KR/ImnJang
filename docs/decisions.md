# 계획 변경 이력

> v1 → v2 → v3 변경 근거와 외부 리뷰 대응 기록.

## 0. v2 → v3 변경 요약

2차 외부 리뷰에서 **v2의 horizon 엔진에 결과를 통째로 무효화하는 버그 3개**가 발견되어 수정했다.

| # | 발견된 버그 | 결과 | v3 수정 |
|---|---|---|---|
| 1 | **자기 건물을 차폐 후보에서 제외하지 않음** | 관측점이 동 중심이므로 자기 폴리곤이 전 방위를 가림 → **모든 단지 일조 0시간** | 후보 집합에서 자기 `building_id` 제외. §6.1 |
| 2 | **높이 기준(datum) 혼용** | 관측 높이는 해발(AMSL)인데 건물 높이는 지면 기준(AGL). 경사지에서 수십 m 오차 | 후보 건물 높이 = `해당 건물 지반고 + 층수×2.8m`. 양쪽 모두 AMSL로 통일 |
| 3 | **near-field densify 간격 부족** | 10m 거리 벽면에서 5m 간격 = **26.6° 공백**. 5° 해상도를 표방할 수 없음 | 거리 비례 adaptive densify. 50m 이내는 edge 샘플링 강화 |

추가 수정 및 개선:

| # | 항목 | 내용 |
|---|---|---|
| 4 | 사실과 다른 표현 정정 | "도로 경계" → **"도로 중심선"**(OSM은 centerline). "도보 10분" → **"추정 도보 10분"** |
| 5 | `river_view` 근거 강화 | "트인 방향에 한강이 있다"와 "한강이 보인다"는 다름. 실제 시선(LOS) 교차 판정을 별도로 수행 |
| 6 | `prediction` 스키마 불일치 수정 | §6.5 본문(면적×층)과 §7 스키마(floor_band)가 어긋나 있었음. **floor_band로 통일** |
| 7 | 매칭 정답셋 50 → **72개 이상 층화 표본** | 50개 전건 정확해도 95% 신뢰구간 하한이 92.9%라 "95% 정확도" 주장을 지지하지 못함 |
| 8 | **조건 완화 추천 기능 추가** (신규) | 조건 만족 단지가 0개일 때 "무엇을 최소로 포기하면 후보가 생기는지" 제시. §6.7 |
| 9 | D3 지연 시 선제 절단 목록 명시 | §10.3 |
| 10 | **ML 학습 데이터 확보 검증 추가** (§5.4) | v2까지 "API가 존재한다"만 확인했고 "11일 안에 받을 수 있는가"는 미검증이었음. **개발계정 일 한도(~1,000건)로 3,000회 호출은 3일 소요** → 학습 데이터는 `rt.molit.go.kr` CSV 벌크로 우회. 셀 커버리지 리스크(R11)도 신설 |
| 11 | **생활 인프라·유동 지표 추가** (§6.8) | 학교·병원·마트·백화점·편의점·공원·야간상권·역 승하차·교통량·건폐율/용적률. 전부 POI 거리 집계라 연산 비용 무시 수준 |

**2차 리뷰에서 반박하여 유지한 결정**

| 쟁점 | 리뷰 의견 | 유지 근거 |
|---|---|---|
| 서울 전역 커버리지 | 1차에서 "6~10 단지로 축소" → **2차에서 철회, 유지가 맞다고 인정** | §3.2 |
| 배치 6시간이 리스크 | 리스크로 지적 | 배치는 D4 저녁 착수 → D5 아침 수령. **사람이 기다리는 시간이 아니다** |
| 반경 1km 부족 | 물리적 horizon 경계가 아니라고 지적 | **일조에 대해서는 수치적으로 충분.** 서울 동지 남중고도 ≈29°, 1km 밖 건물이 29° 앙각을 만들려면 높이 554m 필요 → 롯데월드타워(555m) 하나뿐. 조망 개방도(10° 기준, 176m 이상)에만 부분 유효 → §6.1에 한계로 명시 |

## 0.1 v1 → v2 변경 요약 (이력)

외부 리뷰(codex)와 사실 검증 결과, v1의 두 가지 전제가 **틀린 것으로 확인**되어 계획을 수정했다.

| # | v1의 전제 | 검증 결과 | v2 대응 |
|---|---|---|---|
| 1 | "일조·조망 시뮬레이션은 아무도 안 한다" | **거짓.** 호갱노노·직방이 3D 단지투어로 계절별·시간대별 일조량과 세대별 조망을 이미 제공. 더스택은 "조망권·일조권 정량화"를 내걸고 서비스 중 | 일조·조망은 **기본 기능으로 유지**하되, 차별점 주장을 여기서 하지 않음. 차별점을 §3으로 이동 |
| 2 | "실거래 데이터로 향·층별 가격 기여도를 학습한다" | **불가능.** 공공 실거래 API는 층까지만 제공. **향(向)과 호수가 없고** `aptDong`도 결측이 흔함. 같은 동·같은 층에 남향/북향이 공존하므로 한 거래를 여러 feature 조합에 중복 배정하게 됨 | 세대 단위 SHAP 가격 기여도 **전면 폐기**. 가격 모델을 **단지 레벨**로 강등 |

추가로 반영한 개선:

| # | 개선 | 효과 |
|---|---|---|
| 3 | 일조 엔진과 조망 엔진을 **하나의 horizon profile 엔진으로 통합** | 연산량 6,960만 → 864만 광선. **8배 감소** |
| 4 | 광선-폴리곤 교차를 **꼭짓점 극좌표 변환 + 방위 binning**으로 대체 | 스칼라 루프 → numpy 벡터화. 추가로 수십 배 |
| 5 | 소음 "dB 추정" → **"도로 근접도" 사실 표기**로 강등 | 캘리브레이션 라벨 없이 절대 수치를 주장하지 않음 |
| 6 | 거래-단지 매칭을 `aptSeq` 기준으로 변경 | 단지명 fuzzy match 의존 제거 |
| 7 | 카카오 도보경로 API 배제 (일 1,000건 제한) | 4,000단지 접근성 계산 불가 → 직선거리 + 표고차로 대체 |
