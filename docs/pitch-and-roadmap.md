## 13. 심사 대응

### 13.1 예선 기준 매핑

| 기준 | 대응 |
|---|---|
| 기획력 | "확인이 아니라 탐색" — 경쟁사가 왜 4,000개를 못 다루는지에서 출발한 문제 정의 |
| 실현 가능성 | 동작하는 배포 URL. 서울 전역 실데이터. 운영비 0 |
| 확장성 | Layer 구조. 동일 엔진으로 지역·매물유형 확장. 실거주/투자 양쪽 커버 |
| AI 활용 적절성 | 물리 시뮬레이션 + LightGBM + SHAP. "환각 없는 검증 가능한 AI" |

### 13.2 온라인 투표(20%)

- **단지별 딥링크** `/complex/{aptSeq}` — 자기 동네 검색 → 링크 공유 유도
- OG 이미지에 해당 단지 점수·스카이라인 렌더링
- **서울 전역 커버 → 누가 검색해도 결과가 나온다** (파일럿을 배제한 실질적 이유)

### 13.3 본선 발표 구성 (예선 통과 후 준비)

1. (20초) 문제 — "햇빛 잘 드는 집 찾고 싶은데, 서울 4,000개 단지를 어떻게 다 봅니까"
2. (60초) **시연 — 필터를 건다 → 27개로 줄어든다 → 클릭 → 리포트**
3. (40초) 기술 — horizon profile 단일 연산에서 모든 지표 파생, 8배 최적화
4. (30초) 정직성 — 못 하는 것을 화면에 적어둔 이유, 왜 생성형 AI를 안 썼는가
5. (30초) 확장
